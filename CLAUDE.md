# CLAUDE.md — Phill Portfolio

Cyberpunk-themed developer portfolio for Phill Aelony, live at https://www.phillcodes.com (Vercel). Next.js 16 (App Router, Turbopack) + React 19 + TypeScript + Tailwind 3 + Framer Motion + React Three Fiber, plus the "Shroom Wizard": a 3D character with an AI chat (Claude Haiku) backed by Upstash Redis rate limiting, and the "Jelly Resume": the hero photo dissolves into a 3D, knock-apart copy of Phill's resume at `/resume`.

## Rules

- **Git:** Claude may branch, commit, push and open PRs. Work on a feature branch off `master`; never commit straight to `master`.
- **Version bump** `package.json` in every PR (minor for features/perf, patch for fixes).
- **Accessibility is non-negotiable:** WCAG 2.1 AA, keyboard support on all interactive elements, 44×44px minimum touch targets (that includes `w-11 h-11` on mobile, not `w-10`), visible focus states, `prefers-reduced-motion` respected by every animation.
- **No real Anthropic calls from tests or verification.** Jest mocks the SDK; in the browser, stub `/api/wizard/chat` (e.g. a `fetch` override via an init script).
- **Pick the best tool for each feature; no library is mandatory** (Phill, 2026-10-22: "we should always go with the best tech stack for optimum performance and implementation, we should never be locked to any particular library or stack"). Weigh the options on performance and fit, and say why in the plan. Pull current APIs via context7 (`resolve-library-id` → `query-docs`) or the installed package's own docs and types, not from memory.
  - Today's 3D: R3F + drei where React drives the scene (the Shroom Wizard, the testimonials); plain TypeScript engines where a design tool or mockup was ported 1:1 and the frame loop is the product: the Jelly Resume (`src/lib/jelly/`, raw WebGL2, never mounted for reduced motion) and the Projects vault (`src/lib/vault/`, plain three.js).
  - Whatever the stack, the performance rules hold: a lazy chunk (`next/dynamic` with `ssr: false`, or a dynamic `import()`), one canvas, no setState per frame, paused while hidden.

## Performance Rules

This site is animation-heavy; these are the patterns that keep it fast.

- **Hidden is not unmounted.** A `hidden`/`md:hidden` wrapper still runs a child's canvas, rAF loop and WebGL context. Decide what to mount with `useMediaQuery(MD_UP)` (returns `undefined` until hydrated).
- **Pause offscreen loops.** Use an IntersectionObserver (see `Vortex`) or R3F `frameloop={visible ? 'always' : 'never'}` (see `Testimonials3DCarousel`).
- **Never setState per animation frame.** Mutate refs/attributes inside rAF or `useFrame` (see `useAudioPlayer`'s live `frequencyData`, ShroomMode's filter loop).
- **Keep Three.js code-split.** Import 3D components with `next/dynamic` (`ssr: false`), and never re-export them from a barrel the layout imports. `music/index.ts` deliberately omits `AudioVisualizer` for this reason. Below-the-fold 3D goes inside `<LazyMount>`.
- **Don't declare components inside render** (it remounts them; for a `<Canvas>` that means a new WebGL context).
- **Keep drei props stable.** Changing `Sparkles` `count` rebuilds every particle buffer.
- **Optimize GLBs before committing**, e.g. `npx @gltf-transform/cli resize in.glb a.glb --width 1024 --height 1024` → `webp` → `resample` → `prune` → `meshopt`. drei's `useGLTF` decodes meshopt out of the box. Check the result in the browser.
- To measure: `npm run build && npm run start`, then record a Chrome performance trace with CPU throttling. Count `DrawFrame` events (frames actually drawn); the rAF rate alone hides compositor and raster cost.

## Gotchas

- **Shroom mode wrappers:** `#shroom-target` gets the hue cycle (a Web Animation on desktop, CSS classes on mobile); the inner `#shroom-warp` gets the SVG displacement filter (desktop only, updated ≤30×/s). `MusicPlayer` and `ShroomMode` sit outside both on purpose; don't move them inside. Fixed overlays inside the wrappers (MobileMenu) portal to `<body>`, and the Skill blaster appends its screen-wide effects (`.bl-screen`: beams, bolts, cracks, banners) to `<body>`, because a filter or transform on an ancestor breaks `position: fixed`.
- **Escape layering:** WizardChat handles Escape in the capture phase and stops propagation so the chat closes without also dismissing the wizard (but an Escape from inside an open modal `<dialog>`, the scoreboard, is left to that dialog). The 3D resume does the same (its Esc mustn't also end site shroom mode).
- **3D resume z-order:** `JellyResumeHost` sits in the layout outside `#shroom-target`/`#shroom-warp` (their filters break `position: fixed`). At z-50, DOM order puts it above the page and Nav and below `MusicPlayer` (the site's ♫ stays usable; there is one music player). While it's up, the page, the skip link and `#shroom-ui` are `inert`, and `#shroom-ui` (the wizard sits above it) fades out. Keep `#shroom-ui` a plain wrapper: no filter or transform.
- **The intercepting route:** a soft navigation from `/` to `/resume` renders `@modal/(.)resume` (the overlay over the home page, which stays mounted so the hero can dissolve and the close can land on it); a direct visit or reload renders `app/resume/page.tsx`. `@modal/default.tsx` must exist (returns null). To get the plain page from the home page, hard-navigate or reload (reduced motion and the no-WebGL fallback do).
- **Shared analyser:** the resume dances to the site's player through `src/lib/site-music.ts` (the player registers itself) and taps its `MediaElementAudioSourceNode` with its own 2048-point analyser (`createMusicTap`). Never call `createMediaElementSource` again on that element (it throws), and don't add a second player. `getSiteMusic()?.open()` expands the player's panel (the Experience section's Listen). The Skill blaster plays its synth through the player's own AudioContext (`getSiteMusic()?.context()`, made on the first call, from a click only), pauses the song while it plays (`pause()`), hands it back after (`play()`), and pauses itself when the visitor presses play mid-game (`onChange`). One track at a time.
- **The Skill blaster and the Shroom Wizard:** Esc while the game runs stops only the game (`stopPropagation`; the wizard and shroom mode listen on `window`, after it). No skill lights up under the summoned wizard; the readout centres beside it where that clears it, and on phones the wizard steps aside while the game plays (`src/lib/wizard-aside.ts`; `ShroomWizard3D` walks off and back, its canvas parked).
- **Measuring the 3D resume's cold open:** use a fresh isolated browser context per run (empty caches and a new renderer, so the engine's code runs in the interpreter, as on a first visit) and close other tabs that run the resume. Same-tab reloads keep V8's compiled code and decoded images and look ~2× better. Deferred engine work goes through `nextTask()` (one heavy job per frame); add new load steps there, not in a timeout.
- **WebGL lists uniform arrays by their first element:** look them up as `u['uJoints[0]']`, not `u.uJoints` (which is undefined, and fails silently: the 3D resume's Phill was invisible until this was fixed).
- **The game's Phill has llamas welded to his mesh and skinned to his arms.** Borrowed dances with big arm moves fling them and tear his poncho, so `actors.mjs --arms 1` keeps his idle arms while the rest of him dances. Retargeting note: glTF inverse binds already include the armature (Mixamo's is turned Z-up), so only the clips' local chain gets the armature's turn. What he holds in his left hand had a few leg weights (a sliver stretched hand to knee in the jump); `actors.mjs` re-skins them to the hand (`handHeld`). New Mixamo clips: `fbx2glb.py` (Blender headless), then `--dances …,<clip>.glb` (a file's only clip is named after the file).
- **Per-frame code never reads layout.** `canvas.clientHeight`, `offsetWidth` and friends inside `onFrame`/the engine's frame force a full layout whenever React has just changed the DOM (it cost a 38 ms frame on a 4×-throttled phone when the Play HUD mounted). The engine keeps the canvas's CSS size from its ResizeObserver (`project()`, Play's `viewH()`).
- **Screenshots of sparks:** `__jelly.setTimeScale(0)` blanks the comet sparks (their trails divide by dt); freeze with a tiny scale (0.01) instead. Play's DOM pops ("+300", "!", "TINK!") still run on CSS time and are removed after 900 ms: pause them (`document.getAnimations()`) and hold their timer to catch one.
- **Play survives a hot reload:** a running Play instance keeps the old `play.ts`/`ufos.ts`/`enemies.ts` code after an edit; reload the page. Dev handles: `__jelly.playDev` (`place(line, x)`, `foeAt`, `mushroom`, `shrimp()`, `foes()`, `swells()`), `__jelly.play.input`.
